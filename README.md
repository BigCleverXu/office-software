# reminder-app

桌面端效率工具，把「定时提醒、日历、行情、天气、热点新闻、便签、单机小游戏」收进一个常驻托盘的小窗口。

## 项目概述

应用采用 Electron + Vue 3 + TypeScript 构建，主进程负责数据持久化、系统通知、行情 / 天气 / 热点调度、节假日缓存与版本检查，渲染层只做展示与交互。

### 功能模块

| 模块 | 说明 |
| --- | --- |
| 提醒 | 设定时间与重复规则，到点弹出系统通知 |
| 日历 | 月历含农历、节气与休班标记，支持倒计日与节假日大全 |
| 行情 | A 股与美股指数、自选股行情，交易时段自动刷新，休市自动暂停 |
| 天气 | 实时天气、24 小时温度与降水曲线、7 天预报，常用城市快速切换 |
| 热点 | 聚合 22 个平台的热点新闻，可自选订阅哪些平台 |
| 便签 | 本地记录、置顶与检索 |
| 游戏 | 纯单机小游戏，休闲放松；当前提供像素风「恐龙快跑」 |
| 设置 | 侧边栏底部入口：开机自启、主题、数据目录与备份、检查更新 |

其他能力：

- 系统托盘常驻，关闭窗口默认隐藏到托盘
- 开机自启可选，主题支持浅色 / 深色 / 跟随系统
- 自动检查更新：启动 10 秒后首检、之后每 4 小时一次；发现新版本全局弹窗提醒，同一版本在一次运行内只提醒一次，窗口隐藏时延迟到下次显示再弹出
- 页面状态记忆：重新打开应用会回到上次停留的模块
- 数据库可一键导出 `.db` 备份，便于迁移或留存

## 注意事项

- **关闭窗口不会退出应用**。点击关闭按钮只是隐藏到托盘，提醒调度与行情刷新仍会继续运行；需要彻底退出请使用托盘菜单中的「退出」。
- **提醒依赖系统通知权限**。首次使用时若系统未授权通知，到点提醒将不可见，请在系统设置中允许本应用发送通知；应用需保持运行（可最小化到托盘）。
- **数据保存在本地**。数据库文件为 `office-software.db`，位于 Electron 的 `userData` 目录（例如 Windows 的 `%APPDATA%/reminder-app`、macOS 的 `~/Library/Application Support/reminder-app`）。提醒、便签、倒计日、自选股、常用城市、热点订阅与偏好设置都在其中；卸载或手动清理该目录会导致数据丢失，可在设置页导出备份。
- **行情数据仅供参考**。A 股与美股行情均来自腾讯公开接口，可能存在延迟、停牌或无数据的情况，完整条款见下方「免责声明」。
- **天气、热点与节假日依赖第三方公开接口**。天气数据来自 Open-Meteo，城市联想来自国内行政区划接口，热点新闻来自 `orz-ai/hot_news` 项目，节假日安排来自 `timor.tech`；任一接口不可用时对应模块只会提示加载失败或降级展示，不影响其他功能。
- **安装包未做代码签名**。构建产物由 CI 生成，macOS / Windows 首次运行时可能提示「未知开发者」，需要手动允许后运行。
- **检查更新需要联网**。无法访问 `api.github.com` 时，后台自动检查会静默失败，不会打扰使用；可在设置页手动重试查看具体原因。
- **开发环境版本**。CI 使用 Node.js 22 与 pnpm 10，本地请保持一致，避免 `node:sqlite` 等内置能力不可用。

## 速率限制

### GitHub Releases API（检查更新）

- 检查更新调用 `GET https://api.github.com/repos/BigCleverXu/office-software/releases/latest`，请求未携带任何凭据。
- GitHub 对未认证请求的限制为**每个出口 IP 每小时 60 次**，限制按 IP 统计，与设备数量无关。
- 应用默认在启动 10 秒后首检，之后每 4 小时检查一次，每天约 6 次；设置页的手动检查与自动检查使用同一接口，会额外消耗额度。
- 正常使用远低于上限；若同一网络下多台设备频繁手动检查，或出口 IP 被其他程序大量占用，可能触发限制。此时接口返回 `429`，界面提示「请求过于频繁，请稍后再试」，后台自动检查则静默跳过本次。
- 所有请求超时为 5 秒，失败会归因为网络不可用、超时、限流、发行版信息不可读或未知错误。

### 腾讯行情接口（行情刷新）

- 行情请求地址为 `https://qt.gtimg.cn/q=...`，多只标的会拼接为**一次批量请求**，不会按股票逐只请求。
- A 股交易时段（周一至周五 09:30–11:30、13:00–15:00）每 **3 秒**刷新一次，开盘前 1 分钟开始预热；美股交易时段（美东周一至周五 09:30–16:00）每 **5 秒**刷新一次；休市、午休与非交易日不请求。
- 连续失败 3 次后进入退避，刷新间隔降为 **30 秒**，恢复成功后回到正常间隔；单次请求超时 5 秒。
- 行情页支持「暂停刷新」，暂停期间不发起任何请求；托盘提示文本每 10 秒更新一次，但不额外请求行情接口。
- 请勿修改刷新频率或绕过批量请求逻辑，过度请求可能被数据源限流或封禁 IP。

### Open-Meteo 与城市联想（天气）

- 天气请求地址为 `https://api.open-meteo.com/v1/forecast`，一次取回当前天气、逐时与 7 天预报，无需 API Key；单次请求超时为 10 秒。
- 城市联想仅在输入关键词时请求国内行政区划接口，输入已做防抖；选中城市后按经纬度取天气，不再重复搜索。
- 天气每 **10 分钟**自动刷新一次；切换城市与手动刷新会立即发起请求，快速连续切换只会保留最后一次结果。
- 最多可固定 **12** 个常用城市，城市列表保存在本地，不产生额外请求。

### 热点新闻接口

- 新闻来自 `orz-ai/hot_news` 项目的公开接口，按所选平台**批量**获取，不会逐条请求。
- 仅在进入热点模块、手动刷新或变更订阅平台时请求，页面停留期间不做轮询。
- 默认订阅百度热搜、微博热搜、知乎热榜与 36 氪，可在平台选择中增减，订阅结果保存在本地。

### 节假日接口（日历）

- 节假日安排来自 `https://timor.tech/api/holiday/year/{year}`，按年整年获取并写入本地 `holiday_cache` 表。
- 缓存有效期为 **7 天**，命中缓存不重复请求；日历展示跨年补位日期时最多额外加载相邻两个年份。
- 接口不可用时日历仅显示周末与农历信息，并在顶部提示当年节假日数据暂不可用。

## 开发与构建

### 环境要求

- Node.js 22
- pnpm 10

### 安装与开发

```bash
pnpm install
pnpm dev
```

### 检查与测试

```bash
pnpm run lint
pnpm run typecheck
pnpm run test
```

### 打包

```bash
# Windows
pnpm run build:win

# macOS
pnpm run build:mac

# Linux
pnpm run build:linux
```

推送 `v*` 标签会触发 GitHub Actions 构建三端安装包并发布 Release；版本号以 `package.json` 为准。
